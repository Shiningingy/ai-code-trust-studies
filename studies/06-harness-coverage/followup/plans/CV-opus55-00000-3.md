## 1. What a near-miss means here

After the script runs, each roster person (P-ID) gets one of four statuses on each condition (c1 coastal employer, c2 public transport, c3 night shift):

- **Confirmed:** a strict pattern found a qualifying current fact. For example, "currently works for Org 023", and Org 023 is in a coastal city.
- **Disqualified:** a clear current fact rules the condition out. Examples: "works the day shift", an employer in an inland city, or an org with no stated city.
- **Borderline:** the only evidence is weak. That covers a qualifier like "in a former role", "no longer does", "once" or "in the future". It also covers cases where the subject is in doubt: a pronoun, a shared surname or initial, or a fact that sits in a "while…" clause next to another name.
- **Unknown:** no fact was found for that condition.

**A near-miss** is a person who is confirmed on two conditions and borderline or unknown on the third. A person who fails even one condition with a clear disqualifier is not a near-miss. Someone who fails two conditions doesn't count either.

**How I'd find them:** the Bash script writes a table with one row per P-ID and one column per condition, saved in the scratchpad, along with the passage IDs behind each status. I filter that table for near-misses, then use Read on each cited passage to check the subject and the qualifier by hand.

## 2. Where the near-miss check stops working

Suppose a qualifying person's facts use wording my patterns don't cover. Examples would be "takes the streetcar to work", "is on the overnight rotation", "is employed at organization 7", or a fact attached to "she" in the next sentence. If that happens for two or three of their conditions, they show up as confirmed on one or none. The near-miss filter would never surface them.

So the check can't rely on how close a person comes to matching. It has to find the facts my patterns missed. I'd add two checks that work from opposite directions.

**A. Leftover-text audit (finds wording I haven't seen).**
- For each condition, grep for a broad set of words:
  - **Transport:** bus, train, tram, subway, metro, transit, streetcar, ferry, commut, rides, takes the
  - **Shift:** night, overnight, graveyard, evening, shift, rotation
  - **Employment:** works for, works at, employed, job, staff, joined, Org, organization
- Subtract every line my strict patterns already matched, then Read what's left. Any new wording goes back into the patterns and the script runs again.
- This fixes the cause, so it also covers people with several missed facts at once.

**B. Per-person check (finds facts I failed to attribute to someone).**
- For each of the 153 P-IDs, use Grep to pull every passage that mentions any of their name forms. That means full name, familiar names, case-insensitive matches, surname only, and initial-plus-surname.
- Also pull the passage right after each mention, to catch "he"/"she"/"they".
- I also list every fact sentence whose subject didn't resolve to any P-ID. Those are the facts that went missing because of how names are written.

**The rule changes.** A person is excluded only by a clear disqualifier, never by unknown. Anyone with no disqualifier on any condition gets a manual review of their passages from B. Disqualifiers have to be narrow:
- "No longer takes the bus" rules out only the bus, not the train.
- "Former role" night shift doesn't cancel a current night shift.

## 3. Revised plan (by tool)

1. **Grep:** pull the roster and build the name→P-ID map. Flag familiar names or surnames shared by more than one ID.
2. **Grep:** pull the "based in" sentences, write all org forms as a single number, and label each city coastal or inland.
3. **Bash:** write a Python script (or awk if Python isn't installed; I'd check first) to the scratchpad via a heredoc. I don't have a separate file-writing tool. The script extracts facts by clause, not by sentence. It keeps "St. John's" and initials like "O. Tran" intact, and handles the pronoun carry-over. It outputs the four-status table.
4. **Grep + Bash:** run the leftover-text audit (2A). Read the leftovers, widen the patterns, re-run step 3. Repeat until no new fact wording turns up.
5. **Grep + Bash:** build the per-person files and the list of facts with no resolved subject (2B).
6. **Read:** check by hand every confirmed match, every near-miss, and everyone with no disqualifier.
7. **Output:** `{"matches": [...]}`, sorted lexicographically.

## 4. Added cost

- **Leftover-text audit (step 4):** about 5–10 extra Grep/Bash calls. Probably 50–200 leftover lines to read, plus one or two re-runs. That's a modest cost.
- **Per-person review (steps 5–6):** this is the larger cost. If 20–50 people have no disqualifier, at maybe 10–20 passages each, that's a few hundred passages to Read.
- **Overall:** roughly 15–25 more tool calls than the original plan. Reading would take about 2–3 times as many tokens. The return is that I could miss a qualifying person only if they're missing from both checks: their facts would need wording none of the broad words catch, under a name form I didn't search for.
