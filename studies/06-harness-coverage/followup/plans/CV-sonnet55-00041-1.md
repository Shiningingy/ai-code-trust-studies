## What a near-miss means here

A near-miss is a person who satisfies most of c1–c5 in my extracted table but fails the rest. My table is built from regex patterns, so a failure can mean one of two things:

- **A real failure.** The person doesn't meet the condition.
- **A pattern gap.** The person meets it, but my patterns missed the phrasing, the name variant, or the cross-passage link.

The near-miss check separates these two cases.

**Definition.** For each person, I'd compute k, the number of conditions that pass in the table. I'd define a near-miss as k ≥ 3, which means the person fails at most 2 conditions. For each near-miss, I'd list which conditions failed.

**How I'd find them.** I'd have the script emit a per-person table with a pass/fail column for each of c1–c5. I'd sort it by k and Read the source passages of the near-misses for the failed conditions only. I'd also record weak evidence for each failed condition: partial matches such as one c1 event instead of three, a guardian link with no ward course found, or a food mentioned but not classified. If I find a gap, I'd fix the pattern and rerun.

**Where it stops working.** A near-miss check only works if the person already passes enough conditions in the table. Suppose a qualifying person has facts for several conditions that my patterns miss. Then their k is low, perhaps 1 or 2, and they would never be flagged as a near-miss. Raising the threshold to k ≥ 2 would not fix this, because it would flood the list with people who fail for real reasons.

## Revised plan: audit the patterns, not the people

If the patterns are the problem, I should check the patterns directly instead of looking for people.

1. **Pin down the identifiers.** This is unchanged. I'd Grep for ID forms and the name-to-ID mapping.

2. **Template inventory.**
   - I'd write a script, run through Bash, that splits passages into sentences.
   - It would normalize names, event IDs, youth numbers, foods, and courses into placeholders.
   - It would count the distinct sentence templates.
   - Since the text is templated, I expect this to be a manageable number, probably dozens to low hundreds.
   - I'd Read the full list and label each template as relevant to c1, c2, c3, c4, c5, or none.

3. **Coverage check.**
   - Every template labeled as relevant must be matched by an extraction rule.
   - Every sentence that no rule claims must have a template I've seen and labeled as irrelevant.
   - The script would print any unclaimed sentence template, and I'd fix rules until that list contains only irrelevant templates.
   - Rules must also record the hedged, past, and negated variants, so they can be rejected explicitly instead of silently ignored.
   - As a cross-check, I'd Grep for keywords per condition, such as "volunteer", "guardian", "train", "plane", "enjoys", "dairy", and "cheese". I'd compare those counts with what the rules matched.

4. **Entity resolution.** I'd do this against the full list of name forms from the inventory. I'd keep the merge and split decisions in a file so they can be reviewed.

5. **Aggregate and intersect.** This is the same as before: per-person event sets for c1, the guardian-to-ward-course join, preferences, the fruit and dairy classifications, and then the five-way intersection.

6. **Verification.** I'd Read the source passages for everyone in the result. I'd still do the near-miss review as a secondary check, now on a table I trust more.

7. **Answer.** Only then would I output the JSON.

## Added cost

- **Compute:** negligible. The inventory is one pass over a 471 KB file.
- **Reading:** this is the main cost. I'd read the template list, probably a few hundred lines. That is small compared with reading the 9,322-line file, and I would Read only a few sample passages for ambiguous templates.
- **Iteration:** probably 2–4 extra script runs to get the unclaimed list down to irrelevant templates only.

Overall I'd estimate this adds about 20–30% to the effort of the original plan. In exchange, a qualifying person is no longer missed because of a pattern gap, regardless of how many of their conditions the patterns missed.
