## Plan

1. **Parse into structured records.** I'd write a Python script in the scratchpad that splits the file on `### Passage` headers and then into sentences. Sentence splitting has to cope with initials: "and E." followed by "Laurent" in the next sentence fragment is one name, not a sentence boundary.
2. **Build the identity table.** From the 157 roster sentences, map each P-ID to its canonical name and listed aliases. Then use Grep to look for other identity statements, such as a second roster line for the same name, "not the same person", or two IDs sharing a name. Name matching would ignore case.
3. **Find every phrasing per condition.** Before relying on any regex, I'd use Grep with broad keywords (`dairy|milk|lactose|vegan`, `bus|train|tram|subway|metro|transit|commute|car|cycl|walk`, `works? for|employ|job|Org`, `volunteer|event`) and sort the distinct phrasings with `uniq -c`. Then I'd label each phrasing as current/positive, past, one-off, future, or negated. This step protects against missing people who are described with unusual wording.
4. **Extract facts per condition:**
   - c1: person → organization (current employment only) → city → coastal or not. I'd treat `Org NNN` and `Organization NNN` as the same. If an organization has conflicting city statements, I'd flag it.
   - c2: count **distinct** event IDs with `during this-year` for each person. Duplicate mentions of one event count once. `last-year` and `old-event` entries are excluded. The P-number inside an event name is ignored when deciding who volunteered.
   - c3: only current avoidance counts. "Dislikes eating milk" is a taste, not a choice to avoid dairy, so it doesn't count.
   - c4: only current, habitual public-transport use counts.
5. **Resolve names to IDs.** A full name or a listed alias that points to exactly one ID resolves directly. If an initial plus surname (such as `B. Novak`) fits more than one roster person, I'd record it as ambiguous and not use it to satisfy a condition. In quotes, "I" refers to the speaker.
6. **Intersect and check by hand.** Keep the IDs that pass all four conditions. For every match, and every near-miss that passes three, I'd Grep the person's names and re-read the source sentences to confirm the polarity and timing.
7. **Output.** Print the sorted IDs as `{"matches": [...]}`.

## What could make me miss someone
- Aliases that only appear in lowercase or as initials, or facts split across a sentence break after an initial.
- Paraphrases my regex doesn't catch, like "takes the metro daily" or "is employed by". Step 3 is there to catch these.
- Under-counting events by treating `Org 024`-style variants or other event formats as different things.
- Information buried inside quoted speech or "The volunteer log included some incidental personal information" passages.

## What could make me include someone wrongly
- Counting past, one-off or future statements ("no longer does", "used … once", "plans to") or last-year events.
- Crediting a person with an event because of the P-ID inside its name, or counting the same event twice.
- Tying an initial (`K. Laurent`) to the wrong person when several people share it.
- Treating "Copper Harbor" or a coastal mention in a discussion as an organization's location, or getting a city's coastal status wrong.
