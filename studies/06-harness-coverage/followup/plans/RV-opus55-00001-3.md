## Why the near-miss check falls short

Re-reading only people who fail exactly one condition assumes my patterns find almost everything. A qualifying person whose wording slips past two or more patterns would look like a clear non-match, and nothing would send me back to them. The fix is to check coverage sentence by sentence instead of person by person. Then it doesn't matter how many of one person's conditions were missed.

## Revised plan

Steps 1–4 (roster map, organization-to-city map, the four condition patterns, and working out who each sentence is about) stay the same. I'd add these steps, all in one Python script run with **Bash** from the scratchpad:

**A. Account for every sentence.** Split all 2,370 passages into sentences, and into clauses at "while", "but" and "and" plus a name. Label each clause with exactly one of:
- a positive match for a condition (c1–c4);
- a known exclusion ("no longer", "used to", "plans to", "old-event … last-year", "temporarily skipping", "buys cheese for others", and so on);
- a known irrelevant form (roster sentences, "Organization N is based in X", filler wording that recurs);
- **unexplained**.

Anything my patterns didn't recognize, whether it supports or contradicts a condition, ends up labeled unexplained.

**B. Run a broad keyword net next to the strict patterns.** For each condition, use a wide vocabulary:
- c1: work, employ, job, hired, joined, staff, organization, org
- c2: volunteer, helped, staffed, pitched in, event-
- c3: dairy, milk, cheese, butter, yogurt, cream, lactose, vegan
- c4: bus, train, tram, metro, subway, ferry, transit, commute, rides, pass

Any clause the broad net catches but no strict pattern labeled goes into a residual file, along with every unexplained clause from step A.

**C. Flag sentences with no clear subject.** I'd list separately any clause where I can't work out who it's about: an unknown alias, an ambiguous initial, a pronoun with no clear antecedent, or a quote with no named speaker. A missed name hides facts just as well as missed wording does.

**D. Read the residual file and improve the patterns.** I'd write the residual clauses, grouped by condition and then by person, to a scratchpad file and go through it with **Read**. Each new wording I find becomes a pattern, and I re-run the script until the residual holds only clauses I've read and judged by hand. Every clause in the file either changes the patterns or is consciously set aside.

**E. Check people, then combine.** For each final candidate, and now for **anyone with any residual clause touching any condition**, I'd **Grep** all their name forms and read the hits. That checks for later statements that cancel earlier ones and for duplicate events. Then I intersect the four sets, sort, and output as before.

**F. Run a sanity check on counts.** I'd compare how many fact sentences each person has, by condition. Roster IDs with no c1 or c4 statements at all, or far fewer statements than typical, likely point to missed wording, so I'd Grep those people directly.

## Cost

- **Scripting:** one larger script (clause splitting plus labeling) and probably 2–4 re-runs as patterns improve. That's a few extra Bash calls.
- **Reading:** this is the main cost. The text looks templated, so I expect a few hundred residual clauses, roughly 20–60 KB, read in a few Read calls. The near-miss check was about a dozen Greps. Overall this probably doubles or triples the token use, but it's still well short of reading the whole 469 KB file.
- **Fallback:** if the first residual is huge (say over 150 KB), the patterns are too narrow. I'd improve them using samples before reading everything. Reading the whole file in batches (about 120k tokens) stays available as a last resort.

The plan can still miss things in two ways. A fact could be worded so that it matches an exclusion pattern while actually meaning the opposite, so I'd spot-check a sample of exclusion matches too. And the coastal-city call still depends on general knowledge.
